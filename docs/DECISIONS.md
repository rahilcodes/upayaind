# Decisions log

Choices not covered by docs/SPEC.md, or deliberate deviations. Newest last.

| ID | Decision | Why |
|---|---|---|
| D-001 | **Prisma 7** (`prisma-client` generator + `@prisma/adapter-pg`) instead of Prisma 5/6 classic engine. | Rust-free query engine, smaller serverless bundles, works with Neon/Supabase pooling. Same schema language; spec says "Prisma". |
| D-002 | Added `scripts/migrate-wasm.mjs` (`pnpm db:migrate:offline` / `db:deploy:offline`). | Some sandboxes can't download Prisma's native schema engine. The script uses Prisma's official WASM schema engine and writes standard migrations. CI/Vercel use the normal CLI. |
| D-003 | Schema additions beyond §8: back-relations required by Prisma; `AuthToken` (verify/reset/invite, hashed); `Counter` (invoice numbers); `JdAnalysisCache`; `ProductEvent`; helper fields (`Market.locale`, `StudentProfile.assignmentQueue/awaitingSince/consentVersion/internalNotes`, `Subscription.remindersSent`, `ResumeVersion.jdHash/validation/coverLetter`, `Message.isBroadcast/emailedAt`, `LeaveRequest.coverEmployeeId`, `LoginEvent.email/reason`, `CmsEntry.canonicalUrl/noindex/sortOrder`, `FileObject.studentId/filename`, `MockInterview.durationMin/meetingLink`, `User.lastActiveAt/deletionRequestedAt`). Extra DB constraints: one open WorkSession per employee; non-negative payments. | Needed to implement the flows exactly as specified. |
| D-004 | Env: core variables always required; third-party integrations required in **production** only. In dev/test: emails print to the console, files go to `.local-storage/`, rate limits are in-memory, AI/Stripe actions show a clear "not configured" error. | Lets a developer run the whole app locally while production still fails fast (§14). |
| D-005 | Google sign-in implemented without the Auth.js Prisma adapter (users/accounts are upserted in the `signIn` callback). Staff accounts can't use Google. | JWT sessions don't need the adapter, and our `User` model has required fields the adapter can't fill. |
| D-006 | Staff 2FA: after password login the JWT carries `mfa = setup|verify`; middleware forces `/2fa` until a server-verified TOTP code. The server sends a 60-second HMAC "mfa proof" through `update()` so the client can't self-elevate. | §10: TOTP mandatory for staff. |
| D-007 | Per-role session length enforced inside the JWT (`sessionExpiresAt`: staff 12h, students 7d). Status/role are re-read from the DB every 5 minutes, so deactivation takes effect quickly. | §10. |
| D-008 | Fonts are self-hosted from the Fontsource builds (OFL) via `next/font/local`. | No build-time dependency on Google Fonts; better privacy and LCP. |
| D-009 | CSP allows `'unsafe-inline'` scripts (no per-request nonces). | Nonces force every page to be dynamic, which would break SSG/ISR for the marketing site (§6.1 performance). Everything else is locked down. |
| D-010 | Messages split into one JSON file per area (`src/i18n/messages/en/*.json`). | Keeps copy owned by each feature; still a single next-intl catalogue. |
| D-011 | Seeded US plan prices are **0** (blocked by the price floor) unless `SEED_DEMO_PRICES=1`. Pricing pages show "[Price to be set]" until the admin sets real prices. | §16/§20: prices must be confirmed by the client. |
| D-012 | Old `/blog/*` URLs are not blanket-redirected (the new blog uses `/blog/[slug]`); unknown blog slugs redirect to `/blog` instead. | Avoids breaking new blog posts while still honouring §18. |
| D-020 | **Billing behind `PaymentProvider`** (`src/server/services/billing/`): Stripe implementation (package-default API version) + a Razorpay stub that fails with "not available yet" (P1). Provider picked per `Market.paymentProvider`. Without `STRIPE_SECRET_KEY`, checkout/portal/refund/"Create in Stripe" fail with a clear user-facing message. | SPEC §4 / M2; Razorpay is P1. |
| D-021 | **Dev-only simulated payment.** Only when `NODE_ENV !== "production"` AND Stripe isn't configured, `/app/checkout` shows a "Test mode: simulate payment" step. It builds a synthetic Stripe-shaped `checkout.session.completed` event (with the first paid invoice inline) and runs it through the same `processWebhookEvent()` as `/api/webhooks/stripe`, so activation → invoice PDF → `subscription.activated` (auto-assignment) → notifications are exercised locally and in unit tests. Simulated ids contain `_sim_`; they can't be refunded or opened in the customer portal. | Lets the whole F1 flow be tested offline without weakening "only the webhook activates" (§19). |
| D-022 | **Webhook idempotency = `WebhookEvent` row + processing lease + unique `Payment.providerPaymentId`.** The event is recorded by `event.id`; one delivery claims a 5-minute lease (`error = "processing:<ms>"`), concurrent duplicates get `409` so Stripe retries; processed events are skipped. `providerPaymentId` is the Stripe invoice id (subscriptions) or payment-intent id (one-time), so `checkout.session.completed` and `invoice.paid` for the same charge create one Payment. A `customer.subscription.updated` "active" never activates a never-paid (PENDING_PAYMENT) subscription. | SPEC F1.4 + §12 "structured log line per webhook" (one JSON line per event). |
| D-023 | **Invoice numbers** `UPY-<year>-<6 digits>` come from a per-year `Counter` row (`invoice:<year>`) incremented with a single `UPDATE … RETURNING` inside the Payment transaction; the first number of a year continues after the highest existing (seeded/imported) number. PDFs are rendered with @react-pdf (brand band, business details from `Settings.business[marketCode]`, discount + tax lines), stored privately with purpose `invoice` and the student id, downloaded via `/api/files/<id>`. LETTER for en-US/en-CA, A4 elsewhere. | Sequential, gap-free under concurrency; per-market legal details (§11 Settings). |
| D-024 | **Subscription lifecycle details.** ONE_TIME plans use Checkout `mode=payment`; their period = paid-at + `INTERVAL_MONTHS`. Daily jobs: renewal reminders 13:50 UTC (T-7/T-2, keyed `T7:<periodEnd>` in `remindersSent`, claimed atomically; employee "student expiring" only for plans that will end — one-time/manual/cancel-at-period-end), status sweep 05:20 UTC (one-time/manual → EXPIRED at period end; Stripe plans with no renewal 3 days after period end → PAST_DUE, or CANCELED if set to cancel; PAST_DUE for 21 days → EXPIRED). One pending checkout per student is reused; a student with a live recurring plan is sent to the customer portal instead of a second checkout. Coupons apply to the first payment (`duration: once`); discount terms are locked once used or synced to Stripe. Changing a price's amount clears its (immutable) Stripe price id. | F11 + Stripe semantics; webhooks remain the source of truth. |
| D-025 | **Resume PDFs use static Inter OTFs** in `src/resume/fonts/` (Regular/Italic/SemiBold/Bold, OFL). The variable Inter woff2 used by the web UI embeds in react-pdf but draws blank glyphs (fontkit variable-font issue). Falls back to built-in Helvetica if the files are missing. | ATS-safe real text with the brand font (§9.6). |
| D-026 | **Tailoring runs in a streaming route handler** (`POST /api/resumes/tailor`, NDJSON step events) instead of an Inngest `resume.tailor` job. Inngest jobs exist for `resume.parse` and `resume.render`. | F4 needs live step progress and a < 60 s round trip; a background job would need polling and adds latency. |
| D-027 | **Live preview returns PNG page images** (`POST /api/resumes/preview`, pdf.js + @napi-rs/canvas via pdf-parse) rather than an iframe of a PDF. The global headers (`X-Frame-Options: DENY`, `frame-ancestors 'none'`) block same-origin PDF iframes, and images render consistently on mobile. Download/preview of saved versions: `GET /api/resumes/{id}/{pdf|docx}[?inline=1]`. | Security headers stay strict; typical render 150–400 ms. |
| D-028 | **Without ANTHROPIC_API_KEY** the workspace still works: JD analysis is a deterministic heuristic (skills from the student profile + common list), "tailoring" loads the base resume for manual editing, and resume parsing uses a heuristic text parser. All are flagged (`method: "heuristic"` / `aiUnavailable`). Cover-letter generation shows the "AI isn't configured" error. | Spec §14/D-004: integrations optional in dev; employees shouldn't be blocked. |
| D-029 | **AI cost estimate** comes from env `ANTHROPIC_PRICE_INPUT_PER_MTOK` / `ANTHROPIC_PRICE_OUTPUT_PER_MTOK` (+ `_FAST` variants), USD per million tokens. Unset → costMicros 0 (token counts are always logged). | Prices change and differ per model; not hard-coded. |
| D-030 | **Validator extras beyond §9.4:** contact identity must equal the master profile (the pipeline also re-pins it), education/certifications/projects/awards/languages must be subsets, and numbers absent from the profile produce a *warning* (not a block). Validation runs again on every editor save; a failed result blocks Mark as applied. | Closes obvious loopholes without false positives on rephrasing. |
| D-031 | **Status transitions** are a fixed matrix in `TRANSITIONS` (services/applications.ts); HIRED/REJECTED/WITHDRAWN are terminal, NO_RESPONSE and ON_HOLD can be revived. Managers/admins may force any transition with a note. The NO_RESPONSE sweep uses `lastStatusAt` (time since the last status change). | F5 lists statuses but not the allowed edges. |
| D-032 | **Testimonial request** = daily job that emails students whose OFFER/HIRED event is 7–30 days old, once per student (tracked as ProductEvent `testimonial_requested`). | Inngest-free delay; idempotent. |
| D-033 | **StudentDay counters** are recounted (not incremented) for the day of `appliedAt` in the crediting employee's timezone after every log/import; the workspace "Today x / y" uses the viewer's timezone. Target = active plan's `dailyTarget`. | Idempotent and correct under concurrency/imports. |
| D-034 | **Market variants without dynamic rendering.** Marketing pages render market-specific blocks (prices, plans, phone/WhatsApp, hero copy) once per *active* market inside `data-mk` wrappers; a tiny inline script copies the `market` cookie (or `?market=`) onto `#mk-root[data-market]` before first paint, and generated CSS hides the other markets. Pages stay SSG/ISR (revalidate 3600 + on-demand). Trade-off: HTML grows a little per active market (1 at launch); without JS the default market (US) shows. The switcher links to `?market=XX`, which middleware persists in the cookie. | Reading `cookies()` in a page would make every marketing page dynamic (SPEC §6.1 SSG/ISR + LCP targets). |
| D-035 | **Public CMS images are served at `/media/<fileId>`** (same origin, `purpose = "cms"` PNG/JPEG only, immutable cache). Tiptap image nodes may only point to `/media/…`; external and `data:` images are dropped by the sanitiser. | Works with the strict CSP (`img-src 'self'`) and `next/image`; `/api/files/<id>` stays `no-store` for private files. |
| D-036 | **CMS HTML is generated on the server only**: Tiptap JSON → allow-list sanitiser (nodes: paragraph, heading 2–4, lists, blockquote, code block, hr, hard break, image; marks: bold, italic, underline, strike, code, link with http(s)/mailto/tel/relative hrefs) → `@tiptap/html/server` `generateHTML`. H1 is reserved for page titles (body H1 → H2). Images need alt text to save. Publishing is blocked while text contains `[DRAFT…]` or (stories) `[placeholders]`. | §11 + security: never trust client HTML. |
| D-037 | **CMS conventions:** the About page founder note = PAGE entry with slug `about`; FAQ title = question, body = answer; LEGAL slugs fixed to privacy/terms/refund/guarantee/cookies; soft-deleting an entry frees its slug; revisions = previous versions (newest first, max 20) in `data.revisions`, restore = a new save. STORY structured data: studentName, role, company, companyDomain?, weeksToOffer?, applicationsSent?, quote, photoId/photoAlt?, videoUrl? (YouTube/Vimeo only, embedded via youtube-nocookie/player.vimeo), consentConfirmed. TEAM: name, role, photoId/photoAlt?, linkedin?. | Keeps the CMS schema-free (CmsEntry.data JSON) as specified. |

Cached 24 h (`unstable_cache`, tag `public-stats`); any counter that is 0 is hidden, and the whole strip is hidden when there's nothing real to show. "Hired at" names come from published STORY entries. | §6.2: only numbers the platform actually computed. |

CTAs fire events via `data-track` attributes (one delegated listener), so server components need no client JS. Plan links go to `/signup?plan=…`; for a signed-in student the client swaps them to `/app/checkout?plan=…` (keeps pricing static). | §6.1 tracking + consent; static pages. |

| D-041 | **robots.txt** disallows everything on non-production Vercel deployments (`VERCEL_ENV !== "production"`), and `/app /work /admin /api` plus auth token pages in production. | Keeps staging/previews out of search. |
| D-050 | **Prep PDFs are stored with file purpose `public`** (readable by any signed-in or anonymous user through `/api/files/<id>`, same as CMS media) so students can open them from `/app/prep`. | D-051 | **Admin "today" targets** (overview, students list, below-target list) are computed live: target = active plan's `dailyTarget` on the student's market working days, day boundary = the primary specialist's time zone (market default when unassigned), pro-rated over the specialist's `workSchedule` (start time + hours). | D-052 | **MRR** = Σ active subscriptions' `amountMinor ÷ INTERVAL_MONTHS[interval]` grouped by currency (ONE_TIME counts as 1 month). **Churn this month** = students with a CANCELED/EXPIRED subscription updated this month and no ACTIVE one now; rate = churned ÷ (churned + active). **New students** = first successful payment in the period. | §11 overview definitions not spelled out in the spec. |
| D-053 | **Employee codes** `UPY-####` come from the `employee_code` Counter row (atomic UPDATE … RETURNING; first use continues after the highest existing code; codes taken by hand are skipped). Deactivation sets `DEACTIVATED`, stops new assignments, revokes unused tokens and emits `employee.deactivated` (F2 re-home). | §11 Employees + §3. |
| D-054 | **Account deletion**: admin confirms → `User.deletedAt` + `DEACTIVATED`, active assignments/threads end. Nightly `privacy-purge-deleted` job (02:40 UTC, `jobs/maintenance.ts`) anonymises users deleted > 30 days ago: name/email/phone/password/2FA cleared, profile preferences + master profile + vault secrets + resume content + JD/cover letters + message bodies wiped, non-invoice files deleted. Payments, invoice PDFs, application rows (company/title/date/status) and audit logs are kept (legal/accounting records; §8 "never hard-delete"). Restore is possible until the purge runs. | §10 privacy. |
| D-055 | **Reports** return flat tables shared by the page and the CSV/XLSX route (`/api/admin/reports/{key}?from&to&market&format`). Response = reached RECRUITER_REPLIED or later (status or event); interview = interview record/status; offer = OFFER/HIRED. Role family = first non-seniority keyword of the student's first target title. Retention cohort = month of first payment; retained at +N months when the latest paid period end ≥ first payment + N months. Money in exports is written in major units per row currency. CSV cells starting with `= + - @` are prefixed with `'`. Exports are audit-logged. | §11 Reports. |
| D-056 | **Lead notes** are stored as append-only `AuditLog` rows (`lead.note`) instead of a schema change. Lead statuses: NEW/CONTACTED/QUALIFIED/CONVERTED/LOST. | Avoids a schema change; notes stay attributed and immutable. |
| D-057 | **Notification template overrides** (Settings) replace the email subject, heading and main paragraph as plain text (no placeholders); the in-app bell text keeps the default copy. | Matches how `notify()` applies `settings.notificationTemplates`. |
| D-070 | **Attendance (F8).** Heartbeats insert one `ActivityMinute` per user per minute with `ON CONFLICT DO NOTHING` and also set `User.lastActiveAt`. "Clocked" = session time minus breaks, clipped to the local day in the employee's tz. PRESENT ≥ 240 min, HALF_DAY ≥ 120 min, otherwise ON_LEAVE > HOLIDAY > WEEKEND > ABSENT (working on a holiday or weekend still counts as PRESENT/HALF_DAY). **Holiday region:** staff in Asia/Kolkata use `IN`; everyone else uses the codes of the markets they serve. An hourly job (`attendance-rollup`) auto-closes sessions left open from a previous local day at last activity + 5 min (or at clock-in + 5 min if there was no activity), with `autoClosed=true`, and rolls up yesterday's `EmployeeDay` in the first 3 local hours (or whenever that row is missing). A manager's status override for a day is stored as an AuditLog row (`attendance.day_override`) and wins on every re-rollup. No schema change was needed. | Hourly jobs work for every time zone; corrections stay auditable. |
| D-071 | **Targets (F10).** The RAG compares today's count with `target × elapsed share of the employee's WorkSchedule day` (startTime + hours, employee tz): green ≥ 100 %, amber 60–99 %, red < 60 %, "Target met" when the full target is done, "Inactive" when the subscription isn't ACTIVE, "Day off" when it isn't one of the student market's working days. The below-target alert runs hourly and fires in the hour starting at `belowTargetAlertTime` in the employee's tz; it lists students below 50 % of the **full** daily target, at most once per employee per day; managers get one summary. A nightly `student-day-rollup` sets StudentDay.target to 0 on inactive or non-working days. | Matches the approved "Target pro-rated for 2:40 PM" design. |
| D-072 | **Leave (F9).** Balances are per calendar year, by the request's start date. Carry-forward types add last year's unused quota, capped at one year's quota. Quota 0 means unlimited (Unpaid, Comp-off). Days = schedule working days minus regional holidays; a half day is only allowed on a single date (0.5). Overlap blocks any PENDING or APPROVED request except the opposite half of the same date. Requests may not cross a new year and may not start more than 30 days in the past. A manager can't decide their own request. After approval the UI offers to set cover (`setCover`) for the leave window, using the employee's tz. | Spec leaves the balance rules open. |
| D-073 | **Messaging (F7).** The client polls with a plain visibility-aware `setInterval` (15 s), not React Query, because no QueryClientProvider is mounted app-wide. The unread email is a 5-minute cron that claims messages with `emailedAt` (one email per thread and recipient, never repeated) rather than a delayed job per message. Attachments accept PDF/DOCX/PNG/JPG (≤ 10 MB, max 3); legacy .DOC is rejected because it can't be checked by magic number. Markdown-lite is parsed into React elements, so no HTML strings are ever produced. A COVER employee can write to the student's active thread during the cover window. Managers/admins get read-only access (`getThreadForAdmin`, never marks messages read, audit-logged) via `/work/messages?view=all` and the `<ThreadViewer>` component. | Same UX, simpler infrastructure; safer file handling. |
| D-080 | **Credential vault (§10).** `src/server/services/vault.ts`. Each of username/password/notes is sealed separately (`seal()`, per-value data key). Students see masked metadata and can reveal their own values (not logged as staff access). Staff: `listCredentialsForStaff(user, studentId)` returns metadata only (`canReveal` true only for EMPLOYEE); `revealCredential(user, credentialId, "REVEAL"\|"COPY_USERNAME"\|"COPY_PASSWORD", ip)` works **only for role EMPLOYEE with an active assignment at call time** (managers/admins always refused), writes `CredentialAccessLog` + AuditLog in one transaction and returns the plaintext once with `hideAfterSeconds: 30` (UI re-hides). Soft delete wipes the sealed values (re-sealed as empty) and keeps the row so access logs stay valid. Max 30 entries per student. | Spec §10 + least privilege; logs must survive deletion. |
| D-081 | **Credential access digest** = daily job `credential-access-digest` (13:05 UTC) in `src/server/jobs/notifications.ts`. Includes every un-digested access from before the start of *today in the student's zone* (so late runs never skip rows), groups by person/action/login, claims rows with `digestSentAt` before sending (idempotent under concurrency). | §10 "daily digest of access, not per view". |
| D-082 | **Onboarding (F3).** `onboardingStep` = number of completed steps (0–5); it only ever increases (conditional update). "Fill in manually" starts from `emptyResume`. | Resumable wizard; fast feedback on unreadable scans. |
